# 哲学主义测评站设计规格

日期：2026-10-18

## 1. 项目目标

构建一个无需后端、无需账号、可直接静态部署的中文哲学立场测评网站。网站提供五套中立测评、统一哲学百科、随机名言、立场模拟器、本地历史和结果图片导出。

项目的目标不是提供学术诊断或给用户贴固定标签，而是帮助用户以低门槛方式观察自己的观点分布，并进一步阅读相关哲学概念。所有结果必须明确标注为趣味测评，不宣称科学效力。

## 2. 目标用户与成功标准

目标用户是希望了解哲学概念、比较思想立场或分享测评结果的中文读者，不要求具备哲学专业背景。

成功标准：

- 用户无需注册即可完成任一测试并看到可解释的结果。
- 五套测试均使用中立、无贬义、无现实政治实体的题目。
- 桌面端和移动端均可完成全部流程。
- 结果包含雷达图、维度分数、流派解释和百科入口。
- 用户可将结果保存为包含免责声明的高清 PNG。
- 历史记录只保存在当前浏览器中，且可由用户删除。
- 核心阅读内容和计分不依赖服务端。

## 3. 范围

### 3.1 页面

- `index.html`：站点介绍、五套测试入口、功能入口和隐私提示。
- `lexicon.html`：统一哲学词典、分类筛选、实时搜索和锚点导航。
- `quote.html`：随机展示哲学名言，可点击换一句。
- `simulator.html`：六维人生哲学滑块、实时雷达图和流派匹配。
- `about.html`：项目说明、隐私政策、免责声明和开源声明。
- `history.html`：本地测试历史列表、单条删除和全部清空。
- `mindset/`：心智认知测试。
- `philosophy/`：人生哲学立场测试。
- `metaphysics/`：形而上学与认识论测试。
- `politics/`：政治理念测试。
- `ethics/`：道德伦理测试。

### 3.2 不在首版范围内

- 用户账号、云端同步和排行榜。
- 后端数据库、远程分析和个性化广告。
- AI 自动生成题目或解释。
- 多语言版本。
- 将测评结果解释为心理、人格或政治身份诊断。

## 4. 技术方案

采用原生 HTML、CSS 和 JavaScript 的多页面架构。站点可直接部署到 GitHub Pages、Cloudflare Pages、Netlify、Vercel 静态站点或任意静态服务器。

推荐目录结构：

```text
/
├─ index.html
├─ lexicon.html
├─ quote.html
├─ simulator.html
├─ history.html
├─ about.html
├─ assets/
│  ├─ css/
│  │  ├─ base.css
│  │  ├─ components.css
│  │  └─ pages.css
│  ├─ js/
│  │  ├─ site.js
│  │  ├─ theme.js
│  │  ├─ storage.js
│  │  ├─ test-engine.js
│  │  ├─ results.js
│  │  └─ export-image.js
│  └─ data/
│     ├─ lexicon.js
│     └─ quotes.js
├─ mindset/
├─ philosophy/
├─ metaphysics/
├─ politics/
└─ ethics/
```

每个测试目录包含入口页面、题库、流派配置和页面初始化代码。公共测试引擎负责导航、计分、恢复进度和生成结果，避免五套测试重复实现相同逻辑。

Chart.js 负责雷达图，html2canvas 负责 PNG 导出。两者从 CDN 加载；加载失败时必须保留文字结果和分数列表。

## 5. 视觉与交互

### 5.1 视觉方向

整体采用“现代哲学读本”风格：米白和墨黑双主题，低饱和蓝灰与赭色作为强调色。标题和引文优先使用中文衬线字体，正文和操作控件使用系统无衬线字体。

界面避免游戏化的胜负表达、夸张动效和带评价色彩的结果等级。动画只用于轻量状态过渡，并遵循系统的减少动态效果设置。

### 5.2 通用导航

全站导航包含：首页、主义百科、随机名言、立场模拟器、历史记录和关于网站。移动端折叠为可访问的菜单。主题切换结果保存在浏览器中。

### 5.3 测试流程

- 开始页显示测试目的、维度、题量、预计用时和免责声明。
- 答题页每次显示一道题，提供五档选择、进度、上一题和退出入口。
- 选择答案后可自动进入下一题，同时支持键盘数字键操作。
- 刷新页面后可从本地恢复未完成进度。
- 未完成全部题目时不生成正式结果。
- 结果页显示雷达图、分数、最接近流派、其他相近流派、维度解释、百科链接、重新测试和图片导出。

## 6. 测评与计分模型

### 6.1 通用选择

五档选择分别为：非常不同意 `-2`、比较不同意 `-1`、不确定／视情况而定 `0`、比较同意 `+1`、非常同意 `+2`。

每道题至少作用于一个维度。题库配置明确保存方向和权重，不在题目文字中隐式推断。反向题通过负权重实现。

维度原始得分按该维度理论最大绝对值标准化到 `0–100`，`50` 代表两端相对平衡。所有标准化结果限制在 `0–100` 范围内。

综合流派使用参考坐标表示。匹配度基于用户坐标与参考坐标的归一化欧氏距离计算，并转换为便于比较的相似度。该数值必须称为“模型匹配度”，不能称为准确率或概率。

### 6.2 心智认知测试

- 30 题，4 轴。
- 规则任务导向 ↔ 目标结果导向。
- 外部评价驱动 ↔ 内部自洽驱动。
- 风险规避 ↔ 接纳试错。
- 线性确定思维 ↔ 复杂系统思维。
- 综合类型：任务执行者、自主行动者、平衡型心智。

页面必须明确：规则任务导向是正常认知偏好，在学习和标准化工作中可以构成优势，与其他取向不存在高低或成熟度差异。

### 6.3 人生哲学立场测试

- 36 题，6 轴，每轴至少 6 道主要题目。
- 预设本质 ↔ 自我塑造。
- 客观意义 ↔ 意义开放。
- 接纳秩序 ↔ 主动改造。
- 原则理想 ↔ 实践效果。
- 外部条件 ↔ 个体能动。
- 稳定一致 ↔ 情境演变。
- 匹配流派：存在主义、虚无主义、斯多葛主义、实用主义、本质主义、理想主义。

维度名称用于通俗表达，不宣称这些流派在哲学史上可被六条轴完整概括。模拟器复用本测试的六维配置和流派参考坐标。

### 6.4 形而上学与认识论测试

- 32 题，4 轴，每轴至少 8 道主要题目。
- 唯物取向 ↔ 唯心取向。
- 经验主义 ↔ 理性主义。
- 自由意志论 ↔ 决定论。
- 一元论 ↔ 二元论。

结果首先展示四条相互独立的维度，不把不同哲学问题强行合并成唯一身份。综合摘要只描述用户在本模型中的组合倾向。

页面与百科必须固定说明：本站的“形而上学”采用西方哲学本义，即研究存在、本质与实在的基础哲学学科；并非马克思主义哲学语境中“孤立、静止、片面”的思维方式定义，二者无关。

### 6.5 政治理念测试

- 40 题，5 轴。
- 集体所有制 ↔ 自由市场私有制。
- 强国家 ↔ 无国家。
- 社会平等 ↔ 传统秩序。
- 集体优先 ↔ 个体优先。
- 生态优先 ↔ 经济增长优先。
- 匹配流派：共产主义、资本主义、社会民主主义、民主社会主义、保守主义、古典自由主义、自由意志主义、无政府主义、无政府共产主义。

题目只讨论抽象政治哲学理念，不出现国家、政党、人物或现实事件。社会民主主义描述为在市场经济框架中通过民主制度、社会保障和调节追求公平；民主社会主义描述为通过民主方式推动经济所有权和生产关系的社会主义转型。两者不得互换。

### 6.6 道德伦理测试

- 40 题，4 轴。
- 结果主义 ↔ 义务论。
- 集体福祉优先 ↔ 个体权利优先。
- 德性品格优先 ↔ 规则优先。
- 普世道德 ↔ 情境关怀道德。
- 匹配流派：功利主义、康德义务论、德性伦理学、关怀伦理学。

题目使用抽象、低风险的思想实验，不使用现实灾难、暴力细节或敏感群体场景。

## 7. 百科与内容要求

百科按形而上学与认识论、人生哲学、政治哲学、道德伦理、心智模式五类组织。每个词条包含名称、简短定义、核心主张、容易混淆的概念和稳定锚点。

搜索对名称、别名、定义和关键词进行不区分大小写的包含匹配。分类筛选与搜索条件同时生效。没有结果时显示清晰的空状态和重置按钮。

名言库仅收录可可靠归属的哲学名言；对中文译文不确定的内容使用“意译”标记，出处不能确认时不虚构书名或章节。

## 8. 本地数据与隐私

本地存储使用带版本号的命名空间。允许保存：

- 主题选择。
- 未完成测试的题目版本、当前位置和答案。
- 已完成测试的类别、完成时间、维度分数和结果名称。

不保存姓名、联系方式、自由文本或设备标识。网站不主动上传测评答案。历史页允许删除单条记录或清空全部记录，并在清空前二次确认。

当数据结构版本变化时，优先执行显式迁移；无法迁移的旧数据应被安全忽略或清除，不能导致页面崩溃。

## 9. 图片导出

结果页提供“保存结果图片”按钮。导出区域包含站点名称、测试名称、雷达图、维度分数、主要结果文案和底部固定免责声明“本测试为趣味测评，无学术效力”。

导出时生成适合社交分享的高分辨率 PNG，使用不低于 2 倍像素比例。导出过程暂时使用固定背景和稳定宽度，完成后恢复页面状态。计分数据与显示结果在导出前不得重新计算，以避免图片与当前页面不一致。

## 10. 异常处理与降级

- 题库缺失、题目 ID 重复、维度不存在或分数非法时停止该测试并显示数据错误说明。
- 非法或过期的本地进度不参与计分，并允许用户重新开始。
- Chart.js 加载失败时显示维度分数条形列表和文字结果。
- html2canvas 加载失败时提供浏览器打印或系统截图建议。
- 本地存储不可用时仍可完成当前测试，但明确提示无法恢复进度或保存历史。
- 导航目标不存在时不渲染失效入口。

## 11. 无障碍与响应式要求

- 使用语义化标题、导航、主内容和表单控件。
- 所有交互均支持键盘操作，并有清晰焦点样式。
- 文字和背景满足常规文本至少 4.5:1 的对比度目标。
- 不单独依赖颜色表达维度或状态。
- 在 320 像素宽度下不出现横向滚动。
- 支持系统浅色／深色偏好和减少动态效果偏好。
- 图表提供文字替代内容。

## 12. 验证方案

### 12.1 自动验证

- 检查五套题库的题目数量、唯一 ID、合法权重和维度覆盖。
- 测试正向题、反向题、中立答案、极端答案和混合答案的计分。
- 测试标准化分数始终处于 `0–100`。
- 测试流派距离排序稳定且无非法数值。
- 测试本地历史的写入、读取、单条删除、全部清空和版本迁移。
- 扫描题库中的贬义词、现实政治实体和未替换占位符。

### 12.2 浏览器验证

- 分别完成五套测试的完整流程。
- 验证上一题、刷新恢复、退出、重测和未完成保护。
- 验证主题切换、手机菜单、百科搜索和锚点跳转。
- 验证历史记录的创建和删除。
- 验证浅色与深色主题下的 PNG 导出内容完整。
- 模拟 CDN 加载失败，确认文字结果仍可使用。
- 检查手机、平板和桌面常见尺寸。

## 13. 部署与使用

项目不需要构建步骤。部署时保持目录结构不变并以网站根目录作为静态发布目录。通过本地文件直接打开时，部分浏览器可能限制模块脚本或资源加载，因此开发和验收应使用本地静态服务器；正式部署不受此限制。

## 14. 实施边界

首版以完整、可信和可维护为优先。流派参考坐标属于本项目的解释模型，应在配置和界面中透明表达，不包装为学术共识。任何后续题库修订都需要同步提升题库版本，以避免旧进度与新题目混用。
